# 🤟 SignBridge — AI-Powered Two-Way Sign Language Communication & Learning System

SignBridge captures hand gestures through a webcam, recognizes them in
real time with MediaPipe + a trained ML classifier, and turns them into
text and speech — enabling communication between sign language users and
non-signers, plus an interactive mode for learning sign language.

## Features

| # | Feature | Where it lives |
|---|---------|-----------------|
| 1 | Real-time sign recognition (MediaPipe landmarks + ML classifier) | `src/landmark_utils.py`, `src/predictor.py` |
| 2 | Word/sentence formation with auto-correction | `src/text_buffer.py` |
| 3 | Control gestures — SPACE / BACKSPACE / CLEAR / SPEAK | `src/text_buffer.py`, `src/config.py` |
| 4 | Confidence score + ASL/ISL language switching | `src/predictor.py`, `src/config.py` |
| 5 | Interactive learning mode with progress tracking | `src/learning_mode.py`, `src/learning_content.py`, `utils/progress_store.py` |

## 1. Collect training data

> [!CAUTION]
> **PLACEHOLDER MODEL WARNING**
> The default trained models currently generated by `train_model.py` (if you haven't collected real data) are trained on **SYNTHETIC DATA** (Gaussian noise around random vectors) generated by `generate_synthetic_data.py`. This exists *only* to allow the application to boot without crashing. 
> 
> **They are NOT usable for actual sign recognition.** You *must* collect real webcam data using `src/data_collection.py` and retrain the model before the system can actually recognize your hand gestures.

You need at least one webcam recording session per letter/gesture before
anything can be recognized.

**Two models are shipped:**
- **ASL**: trained on a public Kaggle landmark dataset (13 950 samples, 37 classes,
  99.28% held-out val-accuracy). Performance on your webcam may vary — see the
  domain-gap caveat in the FEATURE_AUDIT.md.
- **ISL**: a **synthetic placeholder** (trained on Gaussian noise vectors).
  100% val-accuracy on noise = 0% on real hands. You must collect real ISL data
  and retrain before ISL mode is usable.

```bash
# Record the full alphabet + control gestures for ASL, ~150 samples each
python -m src.data_collection --language ASL

# Or record specific labels only
python -m src.data_collection --language ASL --labels A B C SPACE BACKSPACE CLEAR SPEAK --samples 200
```

Controls in the capture window: `c` toggles capture, `n` moves to the next
label, `q` quits. Aim for 150–300 samples per label, varying hand angle and
distance slightly for a more robust model. Repeat with `--language ISL` for
Indian Sign Language.

This appends rows to `data/processed/<language>_landmarks.csv`.

## 2. Train the model

```bash
python -m src.train_model --language ASL
# or: python -m src.train_model --language ASL --model mlp
```

This prints a validation accuracy + classification report and saves:
- `models/signbridge_asl_model.joblib`
- `models/signbridge_asl_labels.joblib`

## 3. Run the app

**Full UI (recommended)** — Translate mode + Learn mode, browser-based camera:
```bash
streamlit run app.py
```

**Lightweight CLI** — pure OpenCV window, no browser:
```bash
python cli_app.py --language ASL
```

**Docker (self-contained deployment):**
```bash
# Build and start
docker compose up --build

# App is available at http://localhost:8501
# Models and data are mounted from your local ./models/ and ./data/ directories.

# Run training inside the container (after collecting data into data/processed/)
docker compose --profile tools run train --language ASL
```

> [!NOTE]
> The Docker image uses `opencv-python-headless` (no GUI/display deps). The webcam feed works through the browser via WebRTC — no host display required.


## How recognition works

1. **MediaPipe Hands** extracts 21 (x, y, z) landmarks per detected hand.
2. Landmarks are **translated to the wrist and scale-normalized**, so the
   feature vector is invariant to hand size and distance from the camera.
3. A **RandomForest (or MLP) classifier** predicts a label + confidence
   from the normalized 63-dim vector.
4. Predictions are **smoothed over a sliding window** (majority vote) to
   kill frame-to-frame jitter, then a sign must be **held for N frames**
   before it "commits" (like a long-press), so letters don't spam into the
   text buffer while your hand is moving between signs.
5. Committed letters feed a **TextBuffer**, which accumulates a word,
   applies **spell-check auto-correction** on SPACE, and reacts to control
   gestures (BACKSPACE, CLEAR, SPEAK).
6. **SPEAK** (gesture or button) sends the sentence to `pyttsx3` (offline)
   or `gTTS` (online, more natural voice) for text-to-speech.

## Learning mode

Learning mode (`src/learning_mode.py`) walks the user through short
lessons (e.g. "A–E", "Control gestures", "Spell HELLO"). Each attempt is
checked against the model's committed prediction, logged to
`data/learner_progress.json` via `ProgressStore`, and lessons are marked
complete once every target is matched. This supports **both directions**
of the bridge: a hearing-impaired user can drill precise signing, and a
hearing family member/teacher can learn the alphabet from scratch.

## Extending

- **Add a new language**: add it to `SUPPORTED_LANGUAGES` in `config.py`,
  collect data, train, and add lesson content in `learning_content.py`.
- **Add word-level (not just letter-level) signs**: capture landmark
  *sequences* instead of single frames and swap the classifier for an
  LSTM/temporal model — `predictor.py`'s smoothing logic would need to key
  off sequences rather than single-frame majority vote.
- **Two-hand signs**: Supported by default! Set `MAX_NUM_HANDS = 2` in `config.py` (which is the default). The feature vector is now 128-dimensional (Left/Right slots + presence bits). 
  > [!WARNING]
  > Because of the switch to a 128-dim vector, any models trained prior to this change (which used a 63-dim vector) are now incompatible and will crash. You must re-run data collection and retraining to generate a new model!

## Collecting your own data (required for real recognition)

The synthetic model shipped with this repo **cannot recognise real signs**. It is a placeholder that lets you explore the app and test the pipeline. Follow these steps to replace it with a model that actually works.

### Recommended recording protocol

| Parameter | Value |
|---|---|
| Samples per sign | **150–200** (more if you have time) |
| Lighting | Bright, even, front-facing. Avoid harsh shadows on the hand. |
| Background | Plain or low-clutter. Light background for dark skin, dark background for light skin. |
| Camera angle | Front-facing, hand fills roughly 1/3 of frame. Vary slightly (±15°) across samples. |
| Distance | 40–80 cm from camera. Record at a few distances for robustness. |
| Repetitions | Hold each sign steady for ~1 second, release, repeat. |

### Step-by-step

```bash
# 1. Record the full ASL alphabet + control gestures (~150 samples each)
python -m src.data_collection --language ASL

# Controls in the capture window:
#   c   → toggle capture on/off
#   n   → advance to next label
#   q   → quit
# Data is appended to data/processed/asl_landmarks.csv

# 2. Repeat for Indian Sign Language (ISL)
python -m src.data_collection --language ISL

# 3. Train the classifier
python -m src.train_model --language ASL --source real
python -m src.train_model --language ISL --source real

# 4. A metadata sidecar (models/signbridge_asl_metadata.json) is written automatically.
#    When source=real the synthetic warning banner disappears from the UI.
```

> [!TIP]
> Aim for at least 5 lighting conditions and 3 camera distances across your samples. The biggest source of poor accuracy is training only in one fixed setup then using the app in another.
